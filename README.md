# КЦ1010 на Postgres + Vercel

Перенос системы контроля качества с Google Apps Script.
Цель — **паритет**: те же цифры, те же формы ответов, никаких новых функций.

## Проверка паритета

```bash
createdb kc1010
psql -d kc1010 -c 'CREATE EXTENSION citext;' -f db/schema.sql
export DATABASE_URL=postgresql://...
node scripts/migrate.js dump.json
bash test/run.sh
```

Ожидаемо: **91 проверка, 0 расхождений**.

| тест | что делает |
|---|---|
| `parity.js` | ядро против Apps Script: 5000 чек-листов, 1826 дат, хеши в обе стороны |
| `migration.js` | данные после переноса совпадают с листами |
| `parity-api.js` | обе системы на одних данных, ответы сверяются полем в поле |

`dump.json` — выгрузка листов: `{ "Сотрудники": [[...]], "Журнал оценок": [[...]], ... }`.

## Как подключён фронт

`index.html` перенесён без правок разметки: поменялся только транспорт.

```js
// было
google.script.run.withSuccessHandler(cb).getRgoDashboard(pin, period);

// стало
fetch('/api/getRgoDashboard', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ args: [pin, period] })
}).then(r => r.json()).then(cb);
```

Имена функций и формы ответов совпадают, поэтому обработчики не тронуты. Все 28 вызовов
в разметке остались прежними: `public/gs-shim.js` подключается первым и подменяет
`google.script.run` на `fetch`.

## Решения, которые стоит знать

**Хеши паролей совместимы.** Формат `sha256$1200$соль$хеш` считается одинаково в Apps Script и в Node — проверено в обе стороны. 196 человек входят прежними логинами и паролями.

**Блокировок нет.** Девять точек записи, которые закрывались `withLock_`, защищены транзакциями и уникальными индексами. Дубль заявки и повторная оценка звонка запрещены схемой, а не проверкой в коде.

**Храним только отклонения.** «Положительно» — значение по умолчанию, отсутствие строки означает, что пункт выполнен. Убирает 76% строк ответов: 2564 → 1105 байт на оценку.

**Русские подписи живут в интерфейсе.** В базе — коды `pos/dbt/neg/na/yes/no`, перевод происходит в `lib/api.js` на границе. Фронт получает привычные «Положительно».

## Деплой: Neon + Vercel

1. **Neon.** Создать проект и в нём базу `kc1010`. Строку подключения брать **Pooled**:
   serverless открывает много коротких соединений, прямая строка их не переживёт.
2. **Схема.** В SQL Editor выполнить `CREATE EXTENSION IF NOT EXISTS citext;`, затем
   содержимое `db/schema.sql`.
3. **Данные.** `DATABASE_URL=... node scripts/migrate.js dump.json`.
   Боевой `dump.json` — выгрузка листов; для проверки на пустом месте подойдёт
   `node scripts/seed.js --write`.
4. **Vercel.** Import Git Repository, фреймворк определится сам (Next.js).
   В Settings → Environment Variables добавить `DATABASE_URL` (та же pooled-строка)
   и `PG_POOL_MAX=3`. Deploy.

После деплоя `/` отдаёт интерфейс, а `POST /api/login` с телом `{"args":["логин","пароль"]}`
возвращает токен. Если `/api/*` отвечает «Внутренняя ошибка» — почти всегда это
`DATABASE_URL`: не задан, не pooled или без `?sslmode=require`.

## Локально

```bash
npm install
npm run dev          # свой сервер на scripts/dev-server.js, порт 3000
npm run dev:next     # то же через Next
```

Обоим нужен `DATABASE_URL` в окружении.
