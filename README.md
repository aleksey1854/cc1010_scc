## Запуск локально

Нужны Node 18+ и Postgres 14+ (локальный или Neon).

```bash
npm install
cp .env.example .env      # и вписать свой DATABASE_URL
```

Накатить схему и перенести данные:

```bash
createdb kc1010
psql -d kc1010 -c 'CREATE EXTENSION citext;' -f db/schema.sql
DATABASE_URL=postgresql://... npm run migrate -- dump.json
DATABASE_URL=postgresql://... npm run test:migration
```

`dump.json` — выгрузка листов вида `{ "Сотрудники": [[...]], "Журнал оценок": [[...]] }`.
Такие выгрузки содержат персональные данные и в репозиторий не кладутся — они в `.gitignore`.

## Переменные окружения

| переменная | зачем |
|---|---|
| `DATABASE_URL` | строка подключения к Postgres; у Neon — с `?sslmode=require` |
| `PG_POOL_MAX` | размер пула, по умолчанию 5 (на serverless держим узким) |
| `LEGACY_HARNESS`, `DUMP_JSON`, `FROM_XLSX_JSON`, `GENERATED_JSON` | только для сверки со старым проектом |

Полный список с примерами — в `.env.example`.

## Тесты

```bash
npm test
```

Обе сверки сравнивают новый код со старым проектом на Apps Script. Ни он, ни выгрузки
листов в этот репозиторий не входят, поэтому без переменных `LEGACY_HARNESS` и
`DUMP_JSON` тесты не падают, а сообщают, что сверка пропущена.

## Решения, которые стоит знать

**Блокировок больше нет.** Девять точек записи, которые в Apps Script приходилось закрывать `withLock_`, теперь защищены транзакциями и уникальными индексами. Дубль заявки и повторная оценка одного звонка запрещены на уровне базы, а не проверкой в коде.

**Хеши паролей переехали как есть.** Формат `sha256$1200$соль$хеш` считается одинаково в Apps Script и в Node — проверено в обе стороны. Все 196 человек входят прежними логинами и паролями, сброс не нужен.

**Храним только отклонения.** «Положительно» — значение по умолчанию, отсутствие строки означает, что пункт выполнен. Это убирает 76% строк ответов: 2564 → 1105 байт на оценку.
